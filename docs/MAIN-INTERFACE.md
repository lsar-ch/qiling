# 栖灵 主界面信息架构

## 1. 定位

主界面是 栖灵 的工作台，不是单纯聊天窗口。界面默认使用中文，面向中文用户；中英文切换放在设置里的外观项。

桌面挂件负责常驻、提醒、短反馈和快速入口；主界面负责承载长内容、配置、记忆、知识库和后台任务。

## 2. 展示方式

第一版主界面使用默认浏览器打开。

桌面程序负责：

- 启动本地服务
- 打开浏览器页面
- 传入一次性会话令牌
- 和主界面保持 WebSocket / SSE 通信

主界面负责：

- 展示对话
- 展示任务进度
- 展示执行结果
- 管理设置、记忆、知识库和智能体

## 3. 页面结构

建议第一版保留 6 个页面：

| 页面 | 作用 | 第一版优先级 |
|---|---|---|
| Home | 当前状态、快捷入口、最近任务 | P0 |
| Chat | 文字/语音对话与长回复展示 | P0 |
| Memory | 用户画像、事实、项目进度 | P0 |
| Knowledge Base | Obsidian / 本地知识库入口 | P1 |
| My Agents | Codex 等后台 Agent 状态 | P0 |
| Settings | 模型、语音、角色、权限配置 | P0 |

## 4. Home 页面

Home 是打开主界面后的默认页，参考 DeepTutor 的工作区感觉，而不是普通欢迎页。

建议展示：

- 当前角色状态
- 当前任务状态
- 最近对话
- 最近记忆更新
- 后台 Agent 连接状态
- 常用快捷操作

第一版不要做营销式首页。

## 5. Chat 页面

Chat 页面负责承接：

- 文字输入
- 语音转写结果
- 简单问答结果
- 长回复结果
- 后台任务执行结果

规则：

- 短回复优先在挂件气泡显示
- 长回复自动打开或切到 Chat 页面
- 后台任务结果进入 Chat 页面，同时挂件给短反馈

## 6. Memory 页面

Memory 页面不是数据库列表，而是用户能看懂、能修改的记忆管理界面。

建议分区：

- 用户画像
- 偏好
- 项目进度
- 长期事实
- 最近事件
- 重要决策

第一版重点是可查看、可删除、可手动编辑。

## 7. Knowledge Base 页面

第一版先作为入口和检索页，不急着做完整知识库管理。

建议能力：

- 显示 Obsidian 连接状态
- 搜索知识库
- 打开相关笔记
- 把对话结果写入笔记

写入和修改知识库属于有副作用操作，需要确认。

## 8. My Agents 页面

这个页面负责展示后台执行器，不是让用户直接操作复杂配置。

第一版至少展示：

- Codex 是否可用
- 当前任务队列
- 正在执行的任务
- 最近完成结果
- 权限状态

后续再加入 Claude Code、DeepSeek Harness、云端任务平台。

## 9. Settings 页面

设置页第一版至少包含：

- LLM 配置
- STT 配置
- TTS 配置
 - 角色配置
 - 挂件显示配置
 - 外观语言切换（中文 / English）
  - 权限级别
  - Codex 后台配置

高级配置不要堆在默认视图里，避免第一版界面变复杂。

## 10. 挂件展开规则

挂件双击时打开主界面。

自动展开规则：

- 回复超过短气泡阈值
- 后台任务开始执行
- 需要授权
- 执行失败需要用户处理
- 用户点击气泡详情

不自动展开的情况：

- 简短闲聊
- 简短确认
- 状态提醒
- 无需用户处理的后台进度

## 11. 信息流

```text
用户语音/文字
  → 本地 AI 服务
  → 任务分流
  → 简单回答 / 后台任务
  → 挂件短反馈
  → 主界面长内容或任务详情
  → 记忆归档
```

## 12. 第一版完成标准

第一版主界面完成标准：

- 浏览器能打开主界面
- Home / Chat / Memory / My Agents / Settings 可访问
- 挂件能双击打开主界面
- 长回复能进入 Chat 展示
- Codex 后台状态能展示
- 基础记忆能查看
