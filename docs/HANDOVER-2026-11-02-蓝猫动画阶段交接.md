## 1. 用户已经定下的需求

### 1.1 动作行为

| 状态 | 肢体动作 | 当前计划 |
|---|---|---|
| 待机 | 蹲坐朝前 | `sit_idle` 常驻；眨眼、舔前爪作为短事件轮换 |
| 后台忙碌 | 行走/奔跑切换 | 先 `walk`，达到计时阈值后切 `run` |
| 成功/跳跃 | 跳跃一次 | `jump_once`，播完回到触发前状态 |
| 降级/趴下 | 趴下 | `crouch/down`，按现有状态定义 |
| 点击反馈 | 前爪轻抬等 | `tap_paw_once`，播完回当前状态 |

后续再做：站立挥手、躺下翻滚等扩展互动。

### 1.2 脸部动作

- 待机眨眼；舔前爪时配合头部转向、嘴部轻微动作。
- 说话时需要眼部/头部自然反馈。
- 脸部动作不能依赖某一只猫的骨名或形态键名。
- 正确路线是：`blink / eyeWide / mouthOpen / earForward / headTurn` 等抽象脸部通道，由每个模型的映射 adapter 落到眼睑骨、眼球骨、下颌骨、耳朵骨或 shape key。

### 1.3 工程约束

- v4 的形象、贴图、材质、比例、174 骨骨架和权重已冻结。
- 只允许改动画。若改当前 v4 的脸部权重或新增形态键，先从 v4 建立 v5 冻结基线。
- 每个实施增量都要有最小验证；不要一次性完成所有动作后再集中找 bug。
- 用户后续会替换为其他猫、狗或其他模型；动作必须能复用，不能再次逐动作手调。

## 2. 已拍板的技术路线

```text
状态 trigger
  -> presentation.animal.actions 候选/权重/冷却
  -> 抽象 clip 名（idle / walk / run / jump / crouch / tap_paw）
  -> 离线 retarget 到规范四足骨骼
  -> 目标 GLB AnimationClip
  -> AnimalStage 播放
```

脸部单独走：

```text
抽象脸部通道
  -> 模型脸部 adapter
  -> 眼睑/眼球/下颌/耳朵骨骼或 shape key
```

换模验收标准：

1. 新模型只需提供模型骨骼映射和脸部 adapter。
2. `animal-motion` 抽象动作配置不改，或只做模型能力裁剪。
3. 不在 `AnimalStage` 增加 `if cat / if dog` 分支。
4. 同一 `walk/run/jump` 动画数据可作用于新模型，允许比例缩放，不允许逐动作重 K。

## 5. 已踩坑：不要把这些当成功

### 5.1 “16 骨骼映射通过”不是有效 retarget 证明

`scripts/animal/test_retarget_animal_glb.py` 测的是**当前 v4 目标骨架自己**能否被 profile 找到，没有用原始27骨动作源做端到端断言。

真实源骨名为：

```text
Hips, chest, head, headend, earend, R_earend,
frontleg, frontleg0..2, R_frontleg, R_frontleg0..2,
backleg, backleg0..2, R_backleg, R_backleg0..2,
tailstart, tail, tail1..3
```

首次真实导出日志显示 `mapped: 3`，大量源骨找不到目标骨。因此该结果不能接入运行时。

### 5.2 retarget 的 canonical key 与 v4 目标骨名也没有闭环

`canonical_source_bones()` 返回 `Spine / frontLeg.L / ...` 这类 canonical key，但 v4 目标骨架实际叫：

```text
spine, spine.001..., face, nose, upper_arm.L, forearm.L, hand.L,
thigh.L, shin.L, foot.L, tail.001...
```

`retarget_action()` 目前用 `target_arm.pose.bones.get(name)` 精确查 canonical key。下一步必须显式维护 `canonical -> target bone`，或者让 retarget 中间层真正生成规范骨架后再绑定目标。

### 5.3 导出会混入无关动作

导入目标 GLB 和源 GLB 后，Blender `bpy.data.actions` 同时存在两侧 action。当前 `export_scene.gltf(export_animation_mode="ACTIONS")` 会把未绑定/源侧 action 一起导出。

`work/animal-motion-stage19/idle.glb` 回读后动作名是：

```text
Running, Walking, Walking.001, Walking.002
```

不是预期的 `Walking + idle`。**此文件是无效候选，禁止替换正式 `model.glb`。**

### 5.4 源 action 重命名后会拿回同一个数据块

`retarget_action()` 先把 `source_action.name` 改成 `Retargeted_<name>`，随后又用这个新名字执行 `bpy.data.actions.get(...)`。查找结果就是刚改名的源 action，不是独立的目标 action，源/目标 fcurve 可能混在同一数据块。修导出过滤时必须一并改成显式创建或持有目标 action，不能继续靠名称查找。

### 5.5 正式资产没有被破坏

`data/persona-assets/pet_cat_walk_test/model.glb` 尚未覆盖，仍是 v4 + Walking。所有失败产物都在 `work/animal-motion-stage19/`。
