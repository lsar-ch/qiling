# 栖灵 挂件形象与 2D 资产制作方案

## 1. V1 形态

V1 采用“小型桌面常驻 2D 角色”：

- 透明背景
- 可拖拽
- 可置顶
- 默认低占屏
- 支持双击打开浏览器主界面
- 支持短回复气泡
- 支持程序状态驱动的动画

V1 不直接做 3D，也不要求第一版完成 Live2D。

## 2. 资产路线

推荐采用：

```text
角色设定图
  → 分层 2D 立绘
  → PNG / WebP 资源
  → CSS / Canvas / Web 动画
  → 后续可转换为 Live2D
```

这样可以先验证角色交互和状态反馈，后续再提升表现层，不需要推翻产品架构。

## 3. 角色资产拆分

建议至少拆分以下图层：

- 身体
- 头部
- 头发
- 眼睛
- 眉毛
- 嘴部
- 手臂
- 服装
- 配件
- 状态特效

角色不宜只导出一张合并图片，否则后续无法稳定实现眨眼、口型、表情和动作。

## 4. V1 动画方式

V1 使用轻量动画，不依赖复杂角色引擎。

### 空闲

- 呼吸缩放
- 眨眼
- 轻微浮动

### 聆听

- 身体轻微前倾
- 眼睛或耳朵朝向用户
- 监听提示

### 思考

- 轻微停顿
- 思考符号或小幅循环

### 说话

- 嘴部两到三帧切换
- 配合语音节奏变化
- 显示短回复气泡

### 执行

- 显示任务进行中的动作
- 配合进度或状态提示

### 等待授权

- 疑问表情
- 等待确认的视觉提示

### 完成

- 成功或失败反馈
- 短暂展示后回到空闲

## 5. 资产制作方式

可以使用以下方式制作：

- AI 生成角色草图和设定图
- 人工绘制或修正角色
- 使用图像编辑工具拆分图层
- 统一导出透明 PNG / WebP

AI 生成图适合快速探索风格，但不应直接作为最终可动画资产。
最终资产需要统一角色比例、五官位置、服装细节和图层结构。

## 6. 角色设计约束

第一版建议先做一个示范角色，不要同时制作很多角色。

示范角色可以是：

- 台北办公室女秘书
- 亲切、专业、略带活泼
- 2D 人物
- 简洁服装和清晰轮廓
- 适合缩小后识别

角色设计需要同时服务两件事：

- 小尺寸下能看清状态
- 放大到主界面时不显得过于简陋

## 7. 后续 Live2D 迁移

如果 V1 验证成功，后续可以把现有分层资产迁移到 Live2D：

- 分层 PNG 作为纹理
- 头发、眼睛、嘴部作为可变形部件
- 状态机继续保留
- 只替换 Renderer

因此 `PersonaProfile`、状态机和事件系统不应依赖某一种渲染技术。

## 8. V1 验收标准

- 角色在桌面上清晰可见
- 透明背景无明显黑边
- 拖拽和置顶稳定
- 至少支持空闲、聆听、思考、说话、执行、授权、完成七种状态
- 状态切换与程序事件一致
- 角色资源结构支持后续扩展
