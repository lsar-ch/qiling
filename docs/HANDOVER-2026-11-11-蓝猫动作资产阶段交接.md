### 2.1 等所有动作做完，统一导出一次

现在**不**为 `sit_idle` / `A_rig_walk` 单独改运行时 GLB。依据 Obsidian `07-资产状态与推进计划` §3/§5（v4 不覆盖、冻结指纹前不进运行时）、`06-决策路径` §7、`T-05`（15 个动作入包 + 授权闸门一次过）、`T-07`（授权核验 → 压缩 → 校验）；GLB 是 65MB 单体，每导一次都要整体重写并重做回归。且一次性动作的回落段必须与最终 `sit_idle` / `walk` 边界帧对齐，先定死容易返工。

### 2.2 改循环资产，不改状态机

| 控制器事实 | 内容 |
|---|---|
| `AnimalStage.tsx:354` | gait 非 null 时直接硬用 `walk` / `run`，不读配置映射 |
| `AnimalStage.tsx:367–369` | 固定 `LoopRepeat`；`timeScale` 仅 run→walk 回落时 1.35，其余恒 1 |
| `animalMotion.ts:31` | 解析了 `timeScale`，但 `resolveAnimalClip()` 只返回 clip 名 → **配置里写 timeScale 是死字段** |
| `animalMobility.ts:47–48,214–216` | 位移 80/180 px/s 由代码算，与步频零耦合 |
| `animalLoop.test.ts` | 只断言 `LoopRepeat`，不校验帧数 / 时长 |

控制器对 clip 帧数与时长零假设 → 资产侧做到 `LoopRepeat` + 首尾同相位闭合即可，**零 TS 改动、零回归**。靠 timeScale 调速要改 5 处代码并跑全量 widget 回归，还会连带加速尾巴次级摆动。滑步是独立 P2 问题（`speed = 步幅 × 步频`），与本次周期决策解耦。

### 2.3 导出不含闭合锚点帧，且必须做 C1 对齐

实测两份运行时 GLB 的 `walk` 均为 **0→1.0s / 25 采样 / 24fps / 首末采样值相同**（旧资产含锚点导出），`LoopRepeat` 回绕时连续两帧同姿态、白停一帧。新口径：Blender 保留第 `N` 帧锚点供肉眼验证，**导出只取 0..N-1（28 个采样 / 1.125s）**；仅首尾重合不够，BEZIER 端点手柄会让末段步进偏小，需末 6 帧 C1 对齐，验收 `step(N-1→N)/step(0→1) ≥ 0.98`。
