# DeskMate 桌面感知与任务执行方案

## 1. 目标

让 DeskMate 能看到主人桌面、理解当前工作上下文，并在授权范围内帮主人完成具体操作。

典型任务包括：

- 打开浏览器并搜索
- 点击网页按钮
- 打开视频并全屏播放
- 在应用间切换
- 读取当前窗口标题和页面内容
- 根据上下文判断是否需要介入

## 2. 核心链路

整个能力链路分成四层：

1. 感知：获取桌面、窗口、网页和输入上下文
2. 判断：分析用户当前在做什么，以及助理是否应该介入
3. 执行：点击、输入、切页、搜索、播放、滚动
4. 确认：回显结果，必要时请求授权，失败则回退

## 2.1 感知层级

建议把感知拆成三个层级：

- 窗口级：当前前台应用、窗口标题、窗口状态
- 页面级：URL、DOM 结构、可见文本、表单状态
- 桌面级：截图、OCR、鼠标/键盘动作轨迹、剪贴板

先拿窗口级信息做低成本判断，再按需拉取页面级和桌面级信息。

## 3. 感知层

感知层不只是截图。

建议同时采集：

- 当前活动窗口标题
- 前台应用名称
- 页面 URL
- 页面结构信息
- 屏幕截图
- OCR 文本
- 剪贴板内容
- 最近鼠标和键盘事件

这样模型才有足够上下文判断“主人正在看视频、写文档、查资料，还是在做需要介入的任务”。

## 4. 判断层

判断层负责把原始上下文转成结构化状态，例如：

- browsing
- watching_video
- writing
- coding
- reading_docs
- waiting_for_confirmation
- risky_action

判断层建议再细分两步：

1. 当前场景判断：在看网页、写文档、看视频、编程、待确认
2. 任务可执行性判断：前台执行、后台执行、需要授权、只回答

这里不要让模型直接输出“点哪里”，而是先输出任务意图和风险等级。

## 5. 执行层

执行层分平台处理。

### 5.1 浏览器任务

优先使用浏览器自动化工具，而不是纯鼠标乱点。

适合的动作：

- 打开网址
- 搜索关键词
- 点击网页按钮
- 填写表单
- 播放和全屏
- 翻页和滚动

### 5.2 桌面任务

适合的动作：

- 切换窗口
- 激活应用
- 触发菜单
- 输入文本
- 模拟快捷键

桌面执行不要直接依赖“盲点鼠标”，优先考虑：

- 浏览器自动化
- 无障碍接口
- 系统快捷键
- 稳定的控件定位

纯坐标点击只作为兜底手段。

### 5.3 视频播放示例

你提到的“白龙马”那种体验，本质流程是：

1. 用户输入自然语言要求
2. 系统识别目标视频或应用
3. 打开浏览器或播放器
4. 搜索并进入播放页面
5. 点击播放
6. 全屏
7. 反馈完成结果

## 6. 确认与安全

以下操作默认要确认：

- 登录
- 提交
- 删除
- 支付
- 发送消息
- 修改配置
- 开启高风险自动化

对于低风险任务，可以允许“自动模式”；对于不确定任务，走“辅助模式”；对于纯观察，走“观察模式”。

建议把模式明确成三档：

- `observe`：只看不动
- `assist`：允许低风险执行
- `auto`：允许预设范围内自动执行

默认建议是 `assist`，避免一开始就过度自动化。

## 7. 推荐实现顺序

1. 先实现浏览器任务
2. 再实现桌面感知
3. 再实现有限自动化
4. 最后接入复杂智能体

因为浏览器任务更稳定，最适合先做出“能干活”的感觉。
