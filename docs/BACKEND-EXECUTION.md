# DeskMate 后台执行与 Codex 接入方案

## 1. 目标

DeskMate 的复杂任务不在前台硬做，而是交给后台执行层完成。

这一层的职责是：

- 接收复杂任务
- 选择合适后端
- 管理执行状态
- 处理授权
- 回传结果

## 2. 参考模式

Qwen-Audio-Agent 的公开架构说明了一个清晰路径：

- 前台负责语音入口和用户交互
- 后台通过 ACP 接收任务
- Codex、Claude Code、Qwen Code 等都可以作为后端
- 适配器负责把不同后端统一接入
- 结果再回流到前台

对 DeskMate 来说，这个结构是可借鉴的，但要保持主线是桌面助理，而不是编码平台。

## 3. 推荐架构

```text
用户输入
  → 任务分流
  → Agent Router
  → 后台适配器
      → Codex
      → Claude Code
      → DeepSeek Harness
      → 云端任务服务
  → 结果回流
```

## 4. Codex 接入方式

参考公开资料，Codex 可以通过 ACP stdio 适配器接入：

- `codex-acp` 充当 ACP server
- 它把 ACP 请求翻译成 Codex 操作
- 它再把 Codex 事件映射回客户端

DeskMate 不建议直接把 Codex CLI 的细节写进前端。
更稳妥的方式是：

1. 后台启动 ACP 适配器
2. DeskMate 的 Router 连接这个适配器
3. 通过统一消息结构提交任务
4. 通过统一事件流接收进度和结果

## 5. 任务类型

### 5.1 本地可完成

- 简单问答
- 小范围信息整理
- 低风险界面操作

### 5.2 后台执行

- 代码修改
- 多步骤规划
- 长时间任务
- 需要工具链调用的任务

### 5.3 必须授权

- 删除
- 发送
- 提交
- 支付
- 改配置

## 6. 结果回流

后台执行结束后，DeskMate 需要回传三种结果：

- 挂件短反馈
- 主界面详细结果
- 记忆归档

如果任务中间需要确认，也要回传到主界面和挂件。

### 6.1 已实现（2026-09-15）

- 从对话页分流出的 `delegate_backend` 任务会自动以 `read-only` 起跑，不需要用户再去「我的智能体」点运行。
  只在分流器识别出后台特征（`risk_level != low`，即命中代码/项目/文件/测试等词）时才自动起跑；
  随口一句闲聊只记进任务台，不会拉起真实 agent。
- 自激回环防护：与近期回复近似的输入（扬声器回采，含识别错字）不再起任务，否则
  「起任务 → 播报 → 回采 → 再起任务」会连续自触发真实 run。
- 任务生命周期回写来源会话（`role=tool` 消息）：`▶ 已交给 <执行器>（<模式>）执行`、`⚠ 需要你确认：<操作>`、`✓ 任务完成` / `✗ 任务失败` / `任务已取消`。
- 对话页另有实时状态条（`task.started` / `task.progress` / `task.approval_required` 事件驱动），等待授权时可直接在对话页批准或拒绝。
- 挂件短反馈链路不变；高风险任务仍然先授权、不自动执行。

## 7. 避免跑偏

后台接入不能反向定义产品。

DeskMate 的主结构仍然是：

- 桌面挂件
- 浏览器主界面
- 本地 AI 服务

后台 Agent 只是复杂任务执行层，不是主产品本体。

## 8. 第一版要求

第一版后台接入至少做到：

- Codex 可接
- 任务能进入后台
- 任务状态可见
- 结果可回传
- 高风险任务可先授权
