# 外部项目可借鉴改进建议

> 调研日期：2026-09-12
> 状态：已完成对比；可借鉴项待按路线排期

## 1. 背景

外部桌宠/角色项目的共同方向，是让角色不只聊天，还能观察工作状态、监督 Agent，并在任务完成或需要用户处理时主动反馈。

Project N.E.K.O. 的定位更宽：它把主动陪伴、实时语音、视觉理解、持久记忆、多形态 Avatar、电脑/浏览器操作和插件生态整合成数字生命平台。栖灵 与它的交集是角色化入口、语音、记忆和 Agent 执行，但产品目标仍不同：

- N.E.K.O.：陪伴和角色生命感优先，工作执行是能力之一。
- 栖灵：项目连续性和实际工作交付优先，角色表现服务于工作。

## 3. N.E.K.O. 浏览器与电脑操作实现分析

### 3.1 浏览器操作通道

N.E.K.O. 的浏览器通道由 `brain/browser_use_adapter.py` 适配 `browser-use`，不是直接在前端模拟点击。主要链路如下：

```text
用户任务
  -> BrowserUseAdapter 预检查
  -> 查找 bundled Chromium 或系统 Chrome
  -> 创建/复用 BrowserSession
  -> browser-use Agent
  -> LLM 根据页面状态选择浏览器动作
  -> CDP 执行并回收 AgentHistory
  -> 结果/步骤/失败原因回流
```

关键实现点：

1. **浏览器作为独立执行会话**：通过 `BrowserSession` 管理 Chrome 生命周期，支持复用、检测失效和重建。
2. **CDP 作为控制与观测通道**：通过页面级 CDP session 注入脚本、读取当前页面并处理导航后的状态。
3. **可见浏览器优先**：默认使用可见 Chrome，并在执行期间显示工作中覆盖层，避免用户误以为浏览器卡死或自行操作造成冲突。
4. **模型协议兼容**：优先结构化输出，遇到 schema/参数兼容问题回退到文本模式；按 API 签名缓存可用模式。
5. **有边界的生命周期**：预检查 API、模型和浏览器；任务有超时；支持软取消和拆除 CDP 的硬取消。
6. **结果可观测**：记录每一步动作、目标、错误、提取内容、是否完成和最终结果。
7. **发布适配**：构建时可携带 Playwright Chromium、提示词模板和浏览器扩展缓存，减少首次运行联网下载。

这套方案适合网页搜索、打开页面、填写低风险表单、翻页和提取结果。成本也很明确：浏览器依赖较重、页面变化会影响成功率、登录/验证码/支付等流程必须停下来交给用户。

### 3.2 电脑操作通道

N.E.K.O. 的电脑操作通道由 `brain/computer_use.py` 实现一个截图驱动的 CUA。主要链路如下：

```text
屏幕截图
  -> 压缩到请求预算
  -> VLM 单步输出 Observation/Thought/Action/Code
  -> 解析 Python 动作
  -> pyautogui 执行一次动作
  -> 获取新截图
  -> 重复直到成功、失败、取消或达到步数上限
```

关键实现点：

1. **单步闭环**：每轮只让模型决定一个动作，执行后立刻用新截图验证，降低连续盲操作风险。
2. **结构化提示词**：固定要求观察、思考、动作和代码，模型输出 `pyautogui` 代码或终止动作。
3. **统一坐标投影**：模型可以输出 `0..999` 的归一化坐标，也兼容 `0..1` 和绝对像素；执行前映射到真实屏幕尺寸。
4. **输入兼容处理**：ASCII 使用键盘模拟，中文/emoji 等非 ASCII 文本优先走剪贴板粘贴。
5. **取消和安全边界**：动作前检查取消事件；坐标限制在屏幕范围内，并避开极边缘 failsafe 区域。
6. **截图预算控制**：限制历史截图数量，压缩 JPEG，并把多张图片控制在总请求大小内。
7. **平台降级**：懒加载 `pyautogui`，对 macOS/Windows/Linux 的导入和权限失败返回稳定原因码。

这条通道覆盖任意桌面应用，但不稳定性和风险明显高于 DOM/CDP：模型可能误判控件，系统权限会阻断操作，坐标和窗口布局会变化，且登录、删除、发送、支付等动作不能默认自动执行。

### 3.3 两条通道的选择原则

| 场景 | 首选通道 | 原因 |
|---|---|---|
| 网页搜索、读取、翻页、表单填写 | Browser Use + CDP | 页面级定位比坐标点击稳定 |
| 需要登录态的网页 | 用户现有浏览器会话或可见 Chrome | 需要明确 cookie、验证码和授权边界 |
| 跨应用切换、系统菜单、桌面快捷键 | 原生无障碍/系统快捷键 | 比截图点按更可靠 |
| 无结构化接口的桌面应用 | CUA 截图 + `pyautogui` | 作为最后的通用兜底 |
| 删除、发送、支付、提交 | 任何通道都先授权 | 风险不应由执行器自行推断放行 |

## 4. 栖灵 的借鉴边界

### 4.1 现在值得借鉴

1. **执行通道分层**：浏览器 DOM/CDP、系统无障碍、快捷键、截图 CUA 按可靠性排序，不把所有操作都降级为坐标点击。
2. **预检查和稳定失败原因**：执行前检查浏览器、权限、模型和会话；返回可展示的原因，而不是只抛原始异常。
3. **逐步验证**：每个动作后获取新状态，必要时停止并请求用户确认。
4. **可见执行状态**：执行期间挂件和主界面展示正在操作的任务，保留取消入口。
5. **会话生命周期管理**：浏览器进程、CDP、任务超时和取消必须由执行器统一回收。
6. **结构化历史**：保留步骤、动作、错误和最终结果，便于任务台展示和记忆归档。
7. **插件先做隔离，再做生态**：N.E.K.O. 的插件采用独立进程、异步 IPC、Host/Server 分层；这个隔离思路值得记录，但插件商城暂不建设。

### 4.2 暂时不借鉴

- N.E.K.O. 的完整 CUA 作为默认能力
- Live2D、VRM、MMD 和复杂骨骼动画
- 插件 SDK、插件商城和创意工坊
- 移动端、多设备记忆同步和社交网络
- 大规模多服务商适配
- Steam 发行体系

原因：这些能力会扩大权限、资产、发布和运维边界，当前不能直接提升 栖灵 的项目交付价值。

## 5. 可落地改进建议

### 5.1 任务状态挂件主动播报

已有基础链路，后续只补体验细节：

1. AgentRun 的 `progress` / `milestone` / `waiting_approval` 事件压缩为一句话气泡。
2. 等待授权超过阈值时，挂件轻提醒并给出主界面入口。
3. 完成时播报一句话结论，长内容进入 Chat。
4. 失败或超时提供重试/查看日志入口。

### 5.2 对话模式切换：闲聊 vs 工作

1. 闲聊模式：短上下文、快回复、不加载完整项目记忆。
2. 工作模式：加载项目记忆、允许长推理、优先进入任务分流。
3. 优先级为用户手动选择 > 路由判断 > 默认闲聊。

### 5.3 发布阶段一键安装引导

1. 首次启动检查服务端口、模型 key、语音能力和 Codex 可用性。
2. 缺少 Codex 时明确降级，不阻塞聊天和记忆能力。
3. 退出时回收服务进程。

### 5.4 浏览器窄场景执行器

先实现可验证、低风险的浏览器任务，不实现通用电脑控制：

1. 增加 `BrowserAdapter`，接入现有 Agent Registry，不在前端写浏览器特例。
2. 第一批只支持打开 URL、搜索、读取页面、提取结果、翻页和滚动。
3. 默认使用独立可见浏览器配置；需要用户登录态时明确走现有 Chrome/用户授权流程。
4. 复用 栖灵 的 `AgentRun`、进度事件、取消、授权和结果归档。
5. 每一步记录页面 URL、动作摘要、结果和失败原因；遇验证码、登录、提交时暂停。
6. 先用一个代表性任务验收，再决定是否增加表单填写。

**不建议当前实现**：直接复制 N.E.K.O. 的 `browser_use_adapter.py` 或把 `pyautogui` CUA 搬进 栖灵。应先验证浏览器窄场景是否足以覆盖真实需求。

### 5.5 轻量主动性

在现有任务和表现事件流上增加：

- 项目任务长时间等待提醒
- 任务失败/完成主动短播报
- 记忆更新提示
- 低频项目进度回顾

默认关闭或低频触发，避免把 栖灵 变成主动打扰型桌宠。
