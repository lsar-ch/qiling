# 栖灵 角色形象与互动渐进式规划

> 日期：2026-09-11
> 状态：规划定稿，V1 先实现程序化动态

## 1. 目标

用户只提供一次基础形象，栖灵 负责把它变成可长期运行、可响应工作状态、可逐步增强的桌面角色。

用户不需要手工制作：

- body / eyes / mouth 等图层
- 锚点坐标
- 精灵表
- `layers.json`
- 骨骼或动画参数

栖灵 可以单独运行，也可以选择接入 WorkBuddy、Codex 或其他执行器。角色渲染、互动和状态机不依赖任何外部 Agent。

## 2. 核心架构

```text
用户基础形象
    |
    v
栖灵 资产规范化
    |
    +--> V1：完整图 + 程序化动态
    |
    +--> V1.5：可选完整状态帧
    |
    +--> V2：半自动部件识别与分层
    |
    +--> V3：骨骼/网格/Live2D 类渲染
```

业务状态和视觉动作分离：

```text
业务状态：
idle / listening / thinking / speaking / executing
/ awaiting_approval / completed / interrupted / error

视觉动作：
breathe / float / lean / bounce / shake / wave
/ speak / celebrate / attention / effect
```

同一个业务状态可以根据角色类型映射到不同动作：

- 人物：前倾、点头、手势、身体摆动
- 动物：耳朵、尾巴、跳跃、转头

## 3. 用户流程

### V1 默认流程

```text
上传参考图（可选）
    -> 选择人物或动物
    -> 输入一句角色描述
    -> 生成或导入一张高清基础形象
    -> 用户确认
    -> 栖灵 自动去背景、清理边缘、裁切、对齐、缩放
    -> 立即启用程序化动态
```

用户最终只需要确认一张基础形象。

### V1.5 可选增强流程

用户主动点击“增强动态”后：

```text
基础形象
    -> 系统生成 idle / listening / thinking / success 完整状态帧
    -> 自动统一比例、中心线和脚底线
    -> 用户逐张确认
    -> 失败状态单独重生成
    -> 替换对应状态的程序化表现
```

状态帧是完整图片，不是自动拆出的透明组件。

## 4. V1 资产与动态

### 4.1 输入

支持：

- 用户上传 PNG / WebP / JPG
- 用户从外部图片工具生成后导入
- 栖灵 内部生成基础形象

建议输入为高清、正面或三分之二侧、主体完整、背景简单的图片。输入有瑕疵时，系统做有限清理，不承诺修复严重结构错误。

### 4.2 规范化

栖灵 内部处理：

1. 检测图片尺寸和格式
2. 判断背景并执行去背景
3. 清理明显边缘噪声
4. 找到主体边界
5. 统一中心线、脚底线和安全边距
6. 输出固定画布和多尺寸缓存
7. 写入 栖灵 自有 `asset-manifest.json`

Codex 的精灵表格式只能作为可选导入/导出格式，不能成为 栖灵 运行依赖。

### 4.3 程序化动态

一张完整图即可支持：

- 空闲：呼吸、轻微浮动、偶尔小动作
- 聆听：前倾、轻微脉冲、注意力提示
- 思考：停顿、慢浮动、思考符号
- 说话：整体节奏变化、语音波纹、气泡
- 执行：进度提示、专注姿态、轻微循环
- 等待授权：停顿、疑问提示、提醒气泡
- 完成：弹跳、闪光、成功气泡
- 失败/错误：轻微抖动、错误提示

V1 不承诺真实眨眼、精确口型同步、手臂独立动作或多角度转身。

## 5. QQ 宠物机制的吸收范围

QQ 宠物可借鉴的是：

```text
用户动作
    -> 互动事件
    -> 状态或表现变化
    -> 动画
    -> 气泡/声音反馈
```

栖灵 V1 增加这些轻互动事件：

```text
character.clicked
character.double_clicked
character.dragged
character.hovered
character.woken
character.idle_timeout
```

默认反馈：

- 单击：一次随机小动作或短回应
- 双击：打开主界面
- 拖动：跟随移动，可播放移动动作
- 悬停：注意力动作
- 长时间无操作：低频主动动作，不强制打断工作
- 被唤醒：进入聆听状态并回应

不直接复制 QQ 宠物的：

- 饥饿、清洁、健康衰减
- 生病、死亡和强制照料
- 金币、道具和付费养成
- 好友串门、婚姻、生蛋等社交玩法

这些机制服务于养成游戏，不符合 栖灵 的工作伙伴定位。

## 6. 版本路线

### V1：完整图 + 稳定互动

- 单张基础形象
- 程序化动态
- 业务状态驱动
- 点击、拖动、双击、唤醒互动
- 气泡、语音和状态提示
- 人物/动物动作预设

### V1.5：完整状态帧

- 可选生成 4 张基础状态帧
- 自动对齐和缩放
- 单状态确认和重生成
- 兼容程序化动态作为降级方案

### V2：半自动组件化

- 识别头部、身体、手臂、配件等区域
- 人工确认分割结果
- 只对可靠区域做局部动画
- 眼睛、嘴巴、配件可选替换

### V3：骨骼与高级渲染

- 骨骼定位
- 网格变形
- 多轨道动画和 CrossFade
- Live2D 或其他高级渲染器

状态机、表现事件流和角色卡不随渲染器改变。

## 7. 验收标准

V1 角色功能必须满足：

- 用户只确认一张基础形象即可使用
- 没有 WorkBuddy 或 Codex 时仍能运行
- 角色状态与语音、对话、任务事件一致
- 角色在 150px 左右挂件尺寸下仍可辨认
- 图片有轻微瑕疵时不会阻塞导入
- 严重格式、尺寸或背景问题有明确提示
- 动态不依赖 LLM 直接控制
- 长时间运行无动画计时器泄漏
