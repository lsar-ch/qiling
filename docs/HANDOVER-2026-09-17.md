## 1. 昨夜完成（2026-09-16 → 09-17 00:01）

### 1.1 `60c23c4` fix(agents)：WorkBuddy 授权链路

起因：真机测授权时，界面返回的是**执行内容**而不是授权信息；且「允许一次」被悄悄升级成「永久允许」。

先用探针（`/tmp/wb_probe.py`，报文 `/tmp/wb-probe-traffic.jsonl`）取证，推翻了代码里的旧注释：

| 旧判断（误诊） | 实测真相 |
|---|---|
| Always Ask 下 WorkBuddy 不发 `session/request_permission` | **会发**，Bash 类工具 T+8~15s |
| 不应答会在 10~30 秒后进程退出 | **不会退出**，一直阻塞（探针 110s 强杀，越权操作未执行） |
| 20s 后应答来不及 | 延迟 20s 应答被接受，任务 `end_turn` 成功、文件创建成功 |

据此改四处：

1. `services/ai-service/app/agents/workbuddy.py:268` 模式映射改真值
   - `read-only → plan`（WorkBuddy 的 `plan` 仍会逐个请求授权，不是硬隔离）。真正的只读收口由 `AgentRunManager` 在运行器层自动拒绝授权请求；旧值 `dontAsk` 只是「不弹窗」，写文件跑 Bash 仍被放行。
   - `agent → default`（Always Ask，逐个转 UI 授权）
   - `agent-full-access → bypassPermissions`
   - 未知模式兜底从「静默放行 `dontAsk`」改成 `default`（宁可转授权，卡住由超时兜底）
2. `_option_id_for_kind()` 于 `services/ai-service/app/agents/workbuddy.py:712`
   - WorkBuddy 的 `kind` 与 `optionId` **不同名**：`kind:"allow_once"` → `optionId:"allow"`，`kind:"reject_once"` → `optionId:"reject"`
   - 旧逻辑按 `optionId` 猜 `allow_once`，命中不到 → 落到 `allow_always` → **一次点击变永久放行**
   - 拒绝分支旧返回 `{"outcome":"rejected"}`，ACP 没这个值 → 改 `cancelled`
   - `optionId` 与 `kind` 同名时（Codex 惯例）原样返回，两个执行器共用一套逻辑不回归
3. `_permission_summary()` 于 `services/ai-service/app/agents/runtime.py:31`
   - WorkBuddy 的 `toolCall` **无 title 无 name**，只有 `rawInput.command` / `rawInput.description` / `_meta["codebuddy.ai/toolName"]`
   - 授权卡片按此顺序兜底，不再一律显示「等待授权」
4. 授权 5 分钟超时 `services/ai-service/app/agents/runtime.py:391`
   - 无人值守不能让 run 永远挂 `awaiting_approval`；超时复用**人工拒绝同一条路径**收口并回写会话
   - 两个坑已处理：先把自己从 `_approval_deadlines` 摘掉再调 `approve_run`（否则 `_cancel_approval_timer` 反手取消当前任务，后续会话回流被 `CancelledError` 打断）；用户已决定时定时器被撤销，不会二次拒绝

新增 10 项测试（映射表、`kind` 匹配、全权限自动放行、agent 模式转 UI、摘要提取、超时自动拒绝、手动决定撤销超时）。

> 附带情报：`session/new` 下发的 mode 共 8 档 —— `default`(Always Ask) / `acceptEdits` / `plan` / `auto` / `dontAsk` / `bypassPermissions` / `fullAccess` / `delegate`；另有独立 `sandbox` 开关，当前 `false`（无隔离）。

## 5. 环境与操作要点（踩过的坑）

**进程与端口**
- ai-service `8736`、web dev `5173`、desktop dev `1420`
- 目前 8736 由用户的 `npm run tauri dev` 作为子进程托管，日志 `data/run/ai-service.log`，**不要另起一个抢端口**
- 冷启动首次 `/api/health` 实测 3.25~4.30s 才 200，任何健康检查超时不要低于 8s

**改完代码怎么才生效（最容易踩）**
- 改 `apps/web/**` → 主界面加载的是 **`apps/web/dist` 构建产物**（`app/main.py:145` StaticFiles 挂 `/`），必须 `cd apps/web && npm run build`，光 typecheck 不够
- 改 `apps/desktop/src/**`（挂件）→ vite 1420 HMR，自动生效
- 改 `apps/desktop/src-tauri/**`（Rust）→ `tauri dev` watcher 会重编译并重启 App，没自动重启就手动重启

**验证命令**
```bash
./scripts/check.sh                    # pytest 204 + web/desktop typecheck，约 60s
cd apps/desktop/src-tauri && cargo check
cd apps/web && npm run build          # 改了 web 才需要
```

**Agent 协作注意**
- `apply_patch` 在部分会话会失败 → 用 `exec_command` + python3 heredoc 精确串替换，并 `assert s.count(old) == 1`
- heredoc 里写 `"\n"` 要当心：`<<'EOF'` 引号 heredoc 不做 shell 展开，Python 源码里的 `"\\n"` 是**字面反斜杠+n**，会污染文件（昨夜真踩过，追加测试时在文件里插了一行字面 `\n`）
- 子 agent 只有 `worker` 类型可用（`coding`/`code-review` 报 Model not found）；任务卡必须含责任范围白名单 + 输入路径 + 输出模板 + 验收标准
- 后台进程在回合间会被杀 → 长任务用前台 `exec_command` + 大 `yield_time_ms`

**纪律**
- 新需求：先出方案 + 影响分析，用户同意后再动手
- 不动无关模块，不删别人留下的改动
- API key、音频样本、运行数据、缓存不入库（`apps/web/dist` 已被 `.gitignore:5` 忽略）
- 完成通知 `/Users/lxb/.codex/bin/codex-notify done "..."`；需用户确认用 `need`
