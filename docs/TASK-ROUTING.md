# DeskMate 任务分流规则

## 1. 目标

把用户输入分成四类：

- 纯问答
- 前台可执行任务
- 后台复杂任务
- 高风险任务

这样 DeskMate 才能决定是直接回答、自己做、交给后台做，还是先请求授权。

## 2. 分流维度

任务分流不只看“工作量大小”。

建议同时看三个维度：

- 风险
- 复杂度
- 执行时长

## 3. 分类规则

### 3.1 纯问答

特征：

- 事实查询
- 概念解释
- 文本总结
- 日常聊天

处理方式：

- 前台直接回答

### 3.2 前台可执行任务

特征：

- 操作路径清楚
- 风险低
- 步骤少
- 可快速回显结果

例子：

- 打开网页搜索
- 点击页面按钮
- 展示结果
- 简单整理信息

处理方式：

- 前台执行

### 3.3 后台复杂任务

特征：

- 多步骤
- 多工具
- 需要规划
- 需要长时间执行
- 适合交给 Codex 或其他 Agent

例子：

- 改代码
- 批量处理任务
- 跨应用协作
- 需要持续跟踪状态的任务

处理方式：

- 交给后台 Agent

### 3.4 高风险任务

特征：

- 删除
- 发送
- 支付
- 提交
- 修改配置
- 外部副作用明显

处理方式：

- 必须先授权

## 4. 判定顺序

推荐顺序：

1. 先看是否高风险
2. 再看是否只是纯问答
3. 再看是否可前台快速完成
4. 否则交给后台 Agent

## 5. 判定结果

分流结果建议统一成结构化状态：

- `answer`
- `execute_frontend`
- `delegate_backend`
- `request_approval`

这样后续语音链路、挂件状态机、Agent Router 都可以共用同一套结果。
