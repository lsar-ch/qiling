# 任务拆解流程

1. **明确目标**：用一句话写清"完成后是什么样"；区分目标与非目标。
2. **找关键歧义**：影响范围的未知项先列出，能合理假设就假设并注明，不能假设再询问。
3. **纵向切片**：拆成 3-7 个可独立验证的步骤，每步都保持系统可构建、可运行；避免过大或过碎。
4. **排依赖顺序**：能并行的标明并行，有依赖的严格串行；关键路径放最前。
5. **定验收标准**：每步给出便宜、权威的验证信号（测试输出、构建结果、状态字段、文件存在性）。
6. **标风险**：列出回归风险、需要批准的动作（装依赖、删文件、改配置等）。

输出模板：目标 / 非目标 / 假设 / 步骤清单（含验收）/ 风险与待批事项。
